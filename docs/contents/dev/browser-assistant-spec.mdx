## 文档契约

版本：1.0。调研日期：2026-10-04。状态：目标规格，尚未全部实现。面向产品、设计、扩展、SDK、Lody runtime 和验证工作。

本规格覆盖 ChatGPT 浏览器扩展、Claude in Chrome 已公开的浏览器功能，并规定 Lody 如何实现对应能力。桌面应用、经典侧栏、Cowork 侧栏和第三方服务的能力分别标记。官方资料未明确支持的功能记为“未确认”，不能据此宣称竞品不支持。

“必须”是对应功能交付时的验收要求；阶段表示依赖顺序，不表示功能可以被省略。当前实现与限制由 [Implementation](./browser-assistant-implementation.mdx) 维护；本规格本身不代表功能已交付。竞品事实只由下节维护，其余章节是 Lody 的设计决策，不能反向当作竞品行为。

### 产品和版本边界

ChatGPT 的对照对象是桌面应用配套的浏览器扩展。O1 列出 Chrome、Edge、Brave、Opera 和 Vivaldi；Opera 不提供侧栏聊天，但支持从桌面发起标签页和控制任务。Atlas 独立浏览器及搜索引擎扩展不合并到这个产品的功能承诺中。[O1](https://learn.chatgpt.com/docs/chrome-extension)

Claude 必须区分经典侧栏与 Cowork 侧栏：账号方案、逐步开放及组织设置影响可用界面。录制工作流属于经典侧栏；Cowork 侧栏承接账户会话。Chrome 以外的 Chromium 浏览器不在 C1 的支持声明内。产品页与帮助页对 GA/beta 的表述不同，因此不以“全部正式开放”作为验收前提。[C1](https://support.claude.com/en/articles/12012173-get-started-with-claude-in-chrome)、[C2](https://claude.com/claude-in-chrome)

Claude 的 Manual 在经典侧栏先批准计划，在 Cowork 侧栏逐动作批准；Auto 有动作审查，Skip 不能理解成所有行为都获准。官方仍列出敏感授权要求及交易、永久删除等限制。[C3](https://support.claude.com/en/articles/12902446-claude-in-chrome-permissions-guide) 组织策略与用户批准分层管理，C4 明确未提供 Claude in Chrome 的 ZDR 保证；Lody 的模式与保留政策需要自己的实现证据。[C4](https://support.claude.com/en/articles/13065128-claude-in-chrome-admin-controls)

## 产品目标与当前基线

Lody 扩展是浏览过程中的快捷对话与执行入口。用户应能直接问当前页面、带入资料、审阅结果；需要执行时，Agent 使用指定浏览器中的授权页面。机器、工作区和执行协议由轻量配置和恢复机制承接，不成为每次提问的必填表单。

目标是完整承接上表能力，同时保持默认页面只有会话头部、正文、上下文和输入框。工作流、管理策略、调试器及高级工作区按任务展开。不能通过隐藏尚未完成的协议问题来制造“已可用”的体验。

## UX：入口与日常操作

### UX-01 快捷侧栏

- 点击工具栏打开侧栏并聚焦输入框；新对话只创建本地草稿。打开、关闭、访问设置、选择附件均不得自行提交首条消息。
- 恢复按账号、工作区及会话分区的草稿、附件和滚动位置。切换页面不覆盖正在输入的内容；切换账号立即隔离旧状态。
- 首次配置由设置或紧凑目标选择器完成。目标唯一时可自动选择；失效或多义时说明原因，由用户选择，不偷偷换机器、Agent 或模型。
- 同一窗口默认保持当前会话；页面可绑定已有会话，但绑定必须显式可见。来自右键的新页面先加入待发送上下文，不替换会话。
- 输入框遵循原版 Lody 的光标内联候选：`/` 合并 Agent 命令与已同步 Prompt Shortcuts，`@` 引用获准会话或浏览器标签，`$` 搜索当前机器的技能。键盘选择只替换当前触发范围，保留前后文；Escape 取消候选，输入法组合期间不提交选择。

### UX-02 快捷键、右键与选区入口

- 提供打开/聚焦侧栏的可配置快捷键，遵循平台组合键，不接管网页原有编辑快捷键。快捷键冲突提供浏览器配置入口。
- 右键页面、选中文字、链接、图片分别提供适用的“询问 Lody”。入口冻结事件发生时的 tab、frame、选区或链接目标，之后切换标签不能采集错页。
- 入口形成可编辑草稿，默认不自动发送。已有草稿时合并上下文，保留原文；达到限额时明确指出未加入的资料。
- 框选浮层属于可关闭的增强入口；必须不破坏选择、网页键盘操作和屏幕阅读器。

### UX-03 页面建议与写作

- 空会话提供总结、解释选区、提取要点、翻译和起草回复。建议按已获准的页面类型适配，未授权时不预读正文来生成建议。
- 点击建议填入草稿及对应来源；翻译保留原语言和选区边界。网页内容中的指令不改变模板或权限。
- 写作结果可复制；“插入页面”显示目标字段和替换预览，执行走 ACT-02。目标已变化时重新定位，不能把文字写到后来聚焦的输入框。

### UX-04 Agent、模型与运行配置

- 复用 Lody 官方品牌图标和运行菜单，显示 Agent、模型、思考强度、权限；只显示 runtime 真正支持的 Plan/Fast 等选项。
- 保存实际发送配置到该 turn。能力更新后重新验证；过期配置不能静默降级。既有会话是否允许更换 Agent 由 runtime 能力声明决定。
- 切换模型时检查附件类型、上下文预算及工具兼容性；在发送前给出可操作原因。远端未提供用量时不展示估算余额为真实余额。

### UX-05 状态、通知与无障碍

- 日常连接、读取、上传和发送使用一个紧凑状态区域；等待回复与正在生成属于不同状态。不能同时出现“发送成功”和“发送失败”的互相矛盾提示。
- 完成、需要批准、需要登录和失败可通知；用户首次开启时请求系统权限，拒绝后保留侧栏内通知。通知只含最少元数据，点击定位准确会话/操作。
- 通知按事件 ID 去重；前台正在阅读同一任务时不重复打扰。关闭侧栏不等于停止远端任务。
- 320 × 480、360 × 640、宽侧栏及 200% 缩放下输入、停止和批准可达，无页面横向溢出。工具详情可独立滚动；长命令可换行或在代码区域横滚。
- 使用 Lody UI、StyleX、全局 mood 图标和 Motion springs；Reduce Motion 禁止非必要旋转、位移和 shader。焦点可见，弹层关闭后回到触发器，状态通过适当 live region 宣告且不逐 token 朗读。

## CTX：浏览器上下文

### CTX-01 当前页面与快照

- 输入框显示“使用当前页面”的显式来源开关；默认沿用当前产品的手动附加行为。首次启用说明哪些内容会进入发送；不后台上传所有浏览记录。
- 在发送前采集启用的当前页，冻结 `tabId`、浏览器实例、文档身份和快照版本。消息显示本次实际发送的标题、来源、采集时间及完整/部分状态。
- 已附加快照保持不可变。导航或重新采集产生新版本；旧草稿来源标记“页面已变化”，允许更新、保留或移除，不自动篡改历史。
- URL 需分别保存可公开展示的来源与仅本地可用的导航引用。当前去掉全部 query/hash 可能丢失页面身份；新设计保留经规则批准的定位信息，凭证及敏感参数不得上传。

### CTX-02 正文提取与引用

- 保留标题、段落、列表、表格、代码、链接和语言；过滤隐藏、表单、编辑区和标记敏感内容。对可访问 frame、Shadow DOM、动态内容分段采集并声明覆盖范围。
- 返回 `truncated`、截断原因、实际长度、来源范围和读取错误。不得将正文前 12,000 字符称为完整网页，也不得把空提取结果当成功。
- 长文采用分段/按需读取和预算分配；多来源要可见地说明哪些未送入。总预算取模型、传输及策略限制中的最小值。
- 回复的引用链接指向实际快照或原页面锚点；点击可查看被引用片段。页面变动无法重新定位时打开已保存片段，不能高亮不相关的新内容。

### CTX-03 选区、链接与结构化片段

- 保存选区文本、所在 frame、前后定位锚点和来源；密码、敏感字段以及不可访问 frame 给出明确结果。
- 链接附件区分“链接地址”和“已读取内容”，只有实际取得内容后才显示已读取。图片右键只选择该图片，不等价于授权整页截图。
- 重复附加同一快照可去重；同页不同选区分别保留。发送和显示保持用户选择的来源顺序。

### CTX-04 多标签页与标签组

- `@` 面板列出允许发现的打开标签，支持标题/域名搜索、多选和移除；只发现标签不读取所有标签正文。
- 任务可创建明确的工作标签组。用户把页加入组之前看到共享范围；加入后仍按 GOV-01 校验页面权限。
- 逐页显示读取成功、未授权、关闭、过期和不支持状态。失败页面不被另一页替代；用户可发送可用子集。
- 对比结果保留逐页来源。用户移出标签组即撤销后续访问；已发送快照仍受会话数据策略管理。

### CTX-05 截图与视觉指向

- 支持可见区域截图、框选区域、粘贴图片及拖拽。全页截图是独立能力，不由可见区域截图冒充。
- 捕获前后验证浏览器实例、tab、文档、缩放和滚动位置；不匹配则取消或重新捕获。区域选择 Escape 取消，且不丢失草稿。
- 提供预览、裁剪、移除及可选标注；记录像素尺寸、区域与采集时间。截图是图像输入，不能只提交文件名或 OCR 后冒称视觉理解。
- 图像模型不支持、超限、受保护页面和捕获失败在提交前暴露。跨页面拼接必须检测固定元素和页面变化，并标记局部失败。

### CTX-06 PDF、视频与特殊页面

- PDF 支持本地文件和用户授权 URL，保留页码及引用；文本层、扫描 OCR 和无法解析分别标记。OCR 必须有已配置服务及质量提示，不猜测缺失文字。
- 视频优先读取可访问字幕，保留语言和时间戳，支持跳转定位；没有字幕时说明不可读取，可另行授权转录，不把标题简介当完整视频。
- SPA、无限滚动、Canvas 页面采用能力适配：文本不足可建议截图或受控滚动采集。Chrome 内部页、扩展页、商店限制页和 DRM 失败保持明确。
- 网页登录态只在本地浏览器使用。远程 URL 解析器不能声称继承本机 Cookie；抓取重定向逐跳验证，不能由 URL 输入触发未授权的内网读取。

### CTX-07 浏览历史、书签与记忆

- 历史搜索必须由用户请求触发，限定时间/域名/条数，单次授权；不得默认同步全量历史。查询及返回记录归本次任务。
- 书签支持搜索、选择并附加；新增、移动和删除走单独的操作预览与结果确认。此项是 Lody 扩展要求，不是已确认的竞品书签 UI。
- 个性化记忆必须独立开启，可查看、修改和删除；关闭后新任务不得读取。浏览器访问许可不等于保存长期记忆的许可。
- 无痕模式不持久化本地历史、快照或记忆；首版默认不启用无痕，后续启用须独立隔离和验证。

## FILE：附件与产物

### FILE-01 输入与上传

- 快捷输入支持文件选择、拖拽和图片粘贴，多附件有类型、大小、进度、取消、重试及移除。只有附件且无文字时允许发送，由明确的默认请求或用户补充说明消除歧义。
- 校验以 [SDK 限制](../../../packages/lody-sdk/README.md#attachments) 和当前 Agent 能力为准。传输支持某 MIME 不表示模型能理解；HTML/SVG 等预览不得执行主动内容。
- 草稿二进制存入有账号/工作区隔离的 IndexedDB，不写入 localStorage 或 JSON 转发。空间不足时保留文本，并说明哪些文件未能保存。
- 失败只重试失败附件；成功附件不重复上传。未知上传结果与已确认失败分开，取消不承诺服务端已清理。

### FILE-02 首次发送与附件归属

- 附加文件不得为了上传而创建可见空会话。发送时冻结草稿版本、目标、配置和稳定 request ID，再准备附件并提交一次用户 turn。
- 优先验证 SDK 的 `storageSessionId` 是否允许独立草稿存储身份被新会话消费；这是协议验证项，不是现有后端保证。
- 若不支持独立身份，则在首次发送事务内预留最终 session ID、上传并完成首 turn。失败后保留同一预留与附件身份，恢复不得新建第二段会话。
- 上传成功但发送失败的附件进入待回收记录。没有完成附件删除 API 时不得显示“已从服务器删除”；后端需提供 TTL 或清理协议后才能完成生命周期验收。

### FILE-03 结果预览、下载与分享

- 图片缩略图可打开，文件显示名称、类型、大小和下载入口；文本、代码、PDF 使用适用的安全预览。远端桌面路径不能直接当浏览器可访问 URL。
- 下载失败或凭证过期支持恢复；预览截断明确提示。生成文件必须有可解析的附件引用，只有路径的结果显示可用的桌面打开或重新传输动作。
- 会话导出支持 Markdown 及来源清单；分享默认受账号/工作区访问控制。公开链接需单独选择，展示将包含的附件、来源及权限，撤销后检查实际访问失效。

## CHAT：完整会话

### CHAT-01 历史、搜索与跨端接续

- 侧栏读取同一 Lody 会话，支持分页、标题及全文搜索、重命名、归档、恢复、删除和在主应用打开。搜索不局限于当前加载页，范围必须可见。
- 删除/归档的请求回执不等于远端完成；以权威状态刷新确认。失败保留原列表和可恢复操作，删除草稿与删除云会话分别表达。
- 桌面、侧栏和其他设备显示同一 turn 身份、来源、配置和运行状态。多端同时操作同一 turn 要去重或报告冲突。

### CHAT-02 编辑、重发、分叉与运行中补充

- 用户可复制、编辑重发、重新生成和从指定 turn 分叉；是否可执行由 runtime 能力和权限决定。编辑明确说明后续历史如何变化。
- 重新生成是新的生成请求，不是对未知发送结果换 ID 重试。分叉保留来源会话/turn 和附件引用，并验证用户仍有权读取。
- 运行中输入保留为可编辑草稿；runtime 支持时提供补充指令或排队。发送前显示选择的是补充、排队还是停止后重发，不把三种语义混用。

### CHAT-03 官方内容呈现

- 继续复用/移植官方 Lody 会话组件和排序规则，覆盖正文、代码、表格、思考、工具、计划、目标、系统消息、图片/文件、命令和子 Agent。
- 工具及思考默认紧凑，可展开完整内容；失败、停止、尚无最终答复不能显示为完成。子 Agent 可查看状态和子会话，返回时保留父会话位置。
- 新内容跟随滚动；用户上滚、选择文字或展开记录即暂停跟随。“回到最新”显式恢复。流式更新不得重置打开的详情或焦点。
- 未识别类型保留受控详情及诊断标识，不丢掉记录、不直接铺满 JSON。错误数据不伪造为正常文本。

### CHAT-04 计划、批准与执行反馈

- 计划显示步骤、目标站点和预期副作用，可批准、修改或拒绝；计划批准关联版本，修改站点或关键动作后旧批准失效。
- 运行中批准卡与折叠历史分离，显示动作、对象、原因和批准范围。一个 request 只能产生一个有效决策，多端重复点击返回既有结果。
- 普通进度、浏览器站点授权、Lody Agent 权限和组织拒绝分别呈现。协议原始错误放详情，主文案给出真实原因及下一步，不能用统一“重新读取”覆盖所有失败。

## ACT：浏览器执行

### ACT-01 配对、发现与会话范围

- Agent 通过认证桥接访问用户选定的浏览器实例和 profile；显示运行机器与浏览器所在设备，远端机器不能被误认为拥有本机 Chrome。
- 配对令牌绑定账号、工作区、浏览器实例、会话及有效期。服务能力由握手返回；没有桥接时继续支持文本问答，不显示可执行浏览器操作。
- 断开、注销、工作区切换或权限撤销立即使旧租约失效。任何普通网页脚本都不能调用桥接控制面。
- 使用已有登录态只意味着在授权页面中操作，不导出 Cookie、令牌、密码或整个 profile。

### ACT-02 观察、导航与交互

- 基础动作包含读取语义快照、截图、打开 URL、前进后退、滚动、点击、悬停、输入、按键、选择选项和填表；每个动作声明目标、参数、前置条件与可观察结果。
- 元素引用绑定文档版本；页面导航或 DOM 变化使旧引用失效时重新观察。坐标点击必须校验对应截图、viewport 和滚动，不盲目复用旧坐标。
- 修改输入框与真正提交表单分别授权、执行和记录。写入结果回读确认，不能仅凭点击调用成功声称网站已完成操作。
- 不默认提供任意页面 JavaScript 执行。确需调试求值时，由 ACT-06 的独立能力和权限声明控制。

### ACT-03 标签页、窗口与并发

- 支持创建、发现、激活、关闭、分组和移出任务标签；只操作授权集合。关闭用户原有标签需显式任务依据，临时标签可按任务清理策略关闭。
- 浏览器实例/tab/document 构成目标身份，不依赖“当前激活页”执行远程命令。只读观察可并发，写操作按目标租约串行化。
- 两个任务争用同一页面时显示冲突，等待或由用户接管；不能同时输入导致交错。浏览器重启后旧 tab ID 不自动绑定到新标签。

### ACT-04 网站上传与下载

- 将已选择附件上传到明确的网页字段；核对目标域名、文件清单及接受类型。输入附件授权不自动授权把资料发到任意网站。
- 下载记录文件名、来源、大小、完成状态和本地可用性。取消、浏览器拦截、重复名称和下载失败必须独立处理。
- 本地文件 URL 权限、宿主文件访问与网站权限分别处理；不通过抓取磁盘路径绕过用户选择。

### ACT-05 停止、接管与后台恢复

- 任务在切换标签或关闭侧栏后可继续，前提是宿主和浏览器仍在线。UI 明确显示等待浏览器与实际执行状态。
- “暂停/我来操作”撤销写租约，等待当前动作结果，保留任务；“停止任务”还向 Agent 发取消并阻止新动作。收到取消回执后仍需观察终态。
- 用户接管后重新观察页面，经用户恢复才继续。登录、验证码和支付等要求人工处理的页面提供接管入口。
- MV3 worker 休眠/重启后先恢复操作日志、查明未确认动作，再领取新动作。不可确认的写入不得自动重放；读操作也必须重验目标版本。

### ACT-06 开发与验证工具

- 允许开发 Agent 读取授权标签的 Console、错误、网络摘要及 DOM，按时间窗口和请求范围查询，默认脱敏凭证、请求体和个人信息。
- 支持截图与语义定位反馈，用于修改网站后的浏览器验证；结果包含 URL、viewport、运行版本、时间和实际断言。
- 调试求值、网络正文读取和性能录制分别声明能力及限额。工具不可用时不把空日志当“没有错误”。
- 扩展调试工具不能代替仓库的 Playwright/axe 验收，也不能把本地 fixture 结果写成线上站点实测。

## AUTO：复用与自动化

### AUTO-01 Prompt Shortcuts 与站点工作流

- 保存、搜索、编辑、复制、删除和共享使用原版 Lody Prompt Shortcuts 的身份与协议。同一账号和工作区中的 Desktop 与扩展读取相同目录；打开扩展不创建另一套本地工作流资产，也不要求链接 Desktop。
- `/` 候选在输入框光标位置展开，显示原版命令和可用 Shortcut；选择先将正文与结构化提及加入草稿，不自动发送。远端更新或撤销后，插入前重新核对权限、正文和索引修订；不使用过期正文掩盖读取失败。
- Shortcut 遵循原版 `v: 1` 模型：名称、emoji、slug、说明、prompt、mentions、适用 scope、owner、visibility 和 revision。默认私有；共享后其他工作区成员可读取和复制，只有作者可修改。变回私有不能删除其他成员已经取得的副本。
- 目录权威来自既有云接口，搜索条目来自资源隔离的 Flock 索引，正文来自不可变 Loro 文档。每项资源单独授权；工作区通用 token 不能读取 Shortcut，发布校验旧正文与旧修订，冲突和未同步修改保持可见、可恢复。
- 技能保留 Lody 自身的技能身份，Shortcut 的 mentions 引用技能或其他上游目标，不把技能与 Shortcut 强行合成一个新资产。范围或依赖无法确认时阻止插入并说明；技能紧凑标记及范围随草稿恢复，发送时展开到同一个冻结 prompt。
- 旧扩展本地模板只在用户预览并确认后迁移为私有 Shortcut；保留原记录和稳定迁移身份，重试不重复创建。旧 `{{参数}}` 作为原文保留并提示在草稿中填写；“附加当前页面”不转换成云端执行权限或私有扩展字段。
- 站点适配器仍依赖 ACT 的授权与执行日志，录制产物归 AUTO-02。适配失效时重新观察或停止；参数化步骤、录制及重放不得伪装成现有 Prompt Shortcut wire 字段。

### AUTO-02 演示录制与重放

- 用户显式开始、暂停、停止；持续显示录制状态和范围。只记录选定工作标签，敏感字段不录明文，切出范围时暂停。
- 录制产物先成为可审阅草稿：目标、参数、步骤、站点和完成检查；保存前可删除敏感步骤。取消录制清理本地临时材料。
- 重放依赖语义步骤、运行前条件和结果验证，不是无条件播放坐标序列。页面变化、缺失输入和新站点访问进入暂停/批准状态。
- 桌面全屏和音频演示为独立宿主能力；浏览器版没有这些能力时界面明确范围，不要求扩展偷偷获得全机录制权限。

### AUTO-03 定时任务

- 支持一次性、每日/每周/每月及自定义周期，保存时显示时区、未来三次运行和所需在线设备。修改/暂停/恢复/删除调度与停止当前运行分别操作。
- 每次执行产生独立 `runId`，固定工作流版本、输入、目标和策略快照，保留结果、失败及等待人工处理状态。
- 默认不重叠执行；上一轮未结束则记录跳过。错过执行默认不补跑；用户可选择在限定窗口内补一次。DST 重复时刻只运行一次，缺失时刻跳过并记录。
- 调度触发由一个权威服务负责；浏览器 alarm 只能唤醒/领取，不能与云端各自启动一份。浏览器关闭时本机网站任务显示等待/错过，不能声称云端接管了本地登录态。
- 设置定时授权后，运行仍遵循站点和动作策略；需要新批准时暂停并通知。删除计划后权威查询确认未来触发已停用。

## INT：与 Lody 和配套能力集成

### INT-01 桌面、移动端与开发 Agent

- 同一 Lody session 支持侧栏、桌面和移动端继续对话；浏览器任务绑定执行设备，阅读会话的设备不自动成为执行设备。
- Desktop/CLI 发起浏览器工具请求必须经过 ACT-01 同一桥接，复用会话/操作 ID、批准和停止语义。
- 深链打开对应会话/turn，目标不存在、无权限或机器离线时给出准确说明。跨设备传输附件通过正式附件服务，不复用本地临时 URL。

### INT-02 技能、插件、连接器与服务路由

- 展示所选 Agent 可用的技能、MCP/插件和连接器；支持搜索、显式调用及连接状态，安装/授权使用 Lody 既有管理流程。
- 有专用服务工具时可优先使用，只有浏览器上下文必要时才调用页面；每项活动明确实际执行通道和数据去向。
- 连接器返回内容仍是任务数据。连接器授权、站点授权和组织策略不互相替代，缺连接时不伪造成功结果。

### INT-03 语音输入与对话

- 第一阶段是用户主动开始的听写：显示麦克风状态，结束后文本进入草稿，允许编辑，不自动发送。拒绝权限或网络失败保留已有文字。
- 连续语音是后续独立能力：提供打断、静音、停止、转录及当前页面共享指示；语音说话不自动扩大浏览器范围。
- 默认不保存原始音频；若服务需要保留须在启用前说明策略。模型/服务不支持时隐藏连续对话入口并提供文字方式。

### INT-04 登录与密码管理器

- 优先允许用户在本机页面登录，任务暂停等待。密码和一次性验证码不进入 prompt、截图存档、日志或录制产物。
- 密码管理器集成是能力适配，不假定 Lody 已有 1Password 接口；须验证官方授权方式、宿主条件和凭证直接填充路径。
- 每次凭证请求由密码管理器/系统完成认证；扩展仅收到完成或拒绝结果。登录后重新观察站点状态，不根据填充成功推断已经登录。

## GOV：权限、数据与管理

### GOV-01 分层授权与撤销

- 四层分别是浏览器 API/host 权限、用户站点和任务范围、Agent 动作策略、组织限制；执行需同时满足，组织拒绝优先。
- 支持本次、本站持续允许和拒绝；显示目标 origin、用途及读取/写入范围。撤销立即阻止后续动作，取消队列并使旧批准失效。
- 跨 origin 导航、重定向和跨域 frame 各自检查授权。普通页面不能通过内容、DOM 或消息伪造授权。
- 权限页列出批准范围和历史；浏览器底层已授权不代表用户允许当前任务读取。历史访问与记忆保存使用独立许可。

### GOV-02 执行模式与审批

- 提供只读、询问后操作、按已授权范围执行三类产品语义，映射实际 runtime 能力；模式 ID 来自能力协商，不硬编码成不兼容参数。
- 自动审批只有后端提供真实审查能力时启用，并显示拒绝原因和修改路径。不能把“自动”实现为跳过所有检查。
- 全部跳过审批作为可选兼容能力，仅在 runtime 和组织允许且用户明确选择时提供；永远不绕过浏览器授权、组织限制或桥接身份校验。
- 对外发送、提交、购买、删除及授权变更必须匹配用户已授权的具体目标和范围。范围明确时不重复询问；范围变化或无法判断时展示具体待批准动作。

### GOV-03 组织与部署策略

- 管理员可控制扩展可用性、浏览器执行、录制、调度、连接器、数据保留，以及角色和域名允许/拒绝列表。配置接口属于后端目标，不假设已有。
- 支持强制组织绑定和受管配置。用户看到生效策略及来源；不能通过更换本地 profile 或普通设置覆盖组织拒绝。
- 策略有版本与缓存有效期，写动作使用过期策略时暂停刷新。组织撤销成员立即终止旧身份的新访问。
- Chrome 商店安装和企业管理部署分别验证；不复制竞品的固定套餐名称或逐步开放规则。

### GOV-04 数据生命周期与提示注入

- 网页、文件、字幕、工具和连接器内容统一为不可信资料；不能提升为系统指令、自动创建任务或扩展授权。
- 密钥、Cookie、密码、验证码、支付字段等不采集；检测规则不是零泄露保证，视觉材料必须提供用户预览和移除机会。
- 数据说明区分本地草稿、已上传附件、云会话、诊断及记忆。删除分别报告本地完成、远端待确认和保留限制，不承诺未实现的零保留。
- 默认草稿保留至发送/删除；成功发送后移除无引用本地二进制。上传孤儿需要服务端回收；原始录制默认保存模板后删除，用户显式保留例外。
- 注销删除本机账号凭证、缓存和未发送附件；云会话不随注销删除。执行中的旧身份回调不得重新填回缓存。

### GOV-05 审计、诊断与隐私

- 记录身份范围、动作类型、脱敏目标、策略版本、批准、时间和结果，不默认记录正文、表单值、请求头或截图。
- 用户可查看权限及动作记录；诊断导出前预览范围，包含版本、相关 ID 和错误阶段，凭证永不导出。
- 遥测是否开启由产品/组织策略明确；性能数据不包含用户 prompt。未审计服务端保留政策前不作“完全本地”或“零数据保留”承诺。

## OPS：可用性与兼容

### OPS-01 故障定位与恢复

- 连接状态区分账号未登录、工作区不可用、Agent 离线、浏览器未配对、站点未授权、能力不支持和协议错误。
- 每个失败提供对应动作：登录、选目标、重连、授权、更新、重试读取或查询执行结果；禁止所有错误都显示同一个重试按钮。
- 错误详情提供边界与相关 ID，用户默认视图不堆 UUID 或库级 schema 堆栈。协议错误保持可检查，不用空数据抹平。
- 支持桥接和扩展版本不兼容、代理/网络失败、worker 重启、profile 不匹配及浏览器调试连接争用的诊断。

### OPS-02 平台与发布

- 首个完整支持目标为桌面 Chrome MV3。Edge/Brave/Vivaldi/Opera 作为独立兼容项，逐个验证侧栏、权限、截图、桥接及宿主，不因 Chromium 内核相同就标支持。
- Firefox 保留现有构建入口，新增能力经 capability gating 降级；移动浏览器不承诺安装桌面扩展，可通过 Lody 移动端查看/批准远端任务。
- 无桌面宿主仍可使用已支持的远端文字会话；需要本机浏览器/磁盘/密码管理器的能力明确显示依赖。
- 发布声明列出平台、最低已测版本、实际能力、已知限制和数据政策；最低版本由 API 能力验证和发布矩阵确定，未验证前不得编造版本号。

## 状态、数据与执行契约

### 状态所有权

现有边界以 [Architecture](./architecture.mdx) 为准。下表是扩展能力后的目标分工；新名称为拟建模块职责，不表示文件或服务已存在。

| 状态                             | 所有者                                   | 持久化与失效条件                                                      |
| -------------------------------- | ---------------------------------------- | --------------------------------------------------------------------- |
| 账号、工作区及身份 generation    | account feature                          | 可信扩展存储；注销/切换递增 generation                                |
| 草稿、来源快照和附件引用         | chat/page-context feature                | 分区草稿存储，二进制 IndexedDB；确认发送后按引用清理                  |
| 提交、首次会话预留、未知结果     | conversation feature adapters            | 远端副作用前落 journal；复用原 request ID                             |
| 会话历史、配置及远端运行状态     | SDK + Lody runtime                       | 权威云状态；本地订阅仅投影                                            |
| 浏览器租约、授权、动作 journal   | 拟建 browser-runtime feature             | worker 可恢复存储；身份/策略/文档改变即失效                           |
| tab、frame、元素及截图引用       | 拟建 browser-context adapter             | 绑定浏览器 epoch 和文档版本，不跨重启复用                             |
| Prompt Shortcuts、计划及调度运行 | automations feature + SDK + 权威调度服务 | 资源隔离的目录/正文、不可变发布修订；调度运行去重和领取租约           |
| 外部协议与服务 I/O               | SDK infrastructure 或宿主 adapter        | 显式 origin/凭证；SDK domain/application 不依赖 WXT、React 或设备存储 |

WXT entrypoints 只挂载界面和注册生命周期。产品桥接不引入 Node 到扩展；需要原生宿主的部分属于 Lody 主机产品，Node 开发工具继续放 `tools`。现有网络转发白名单保持原职责，不能变成任意 URL、任意方法或任意脚本执行入口。

### 目标数据模型

以下列出状态模型必须保留的语义。Prompt Shortcut 已有上游 wire 合同，以 [SDK shortcuts](../../../packages/lody-sdk/src/shortcuts) 和 [Lody 原版模型](../../../vendor/lody/packages/shared/src/prompt-shortcuts/model.ts) 为准；其余目标模型的正式字段名、版本和大小上限须经协议实验及端到端合同确认。

| 实体               | 必要字段                                                                                                                             | 约束                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| ContextSnapshot    | id、schemaVersion、kind、scope、source、capturedAt、revision、contentHash、coverage、truncated、payloadRef                           | 不可变；kind 覆盖 page/selection/link/image/pdf/transcript/history；资料 trust 固定 untrusted |
| SourceLocator      | browserInstanceId、epoch、tabId、frameId、documentId、displayUrl、localNavigationRef                                                 | 展示与执行定位分离；跨身份不可复用本地引用                                                    |
| DraftAttachment    | id、draftId、scope、kind、name、mime、size、blobRef、uploadState、remoteRef                                                          | 单附件独立恢复；binary 不进入普通日志                                                         |
| SubmissionEnvelope | requestId、scope、target、draftRevision、prompt、inputBlocks、contextRefs、runConfig、payloadHash                                    | 同 ID 内容不可变；恢复不得重采页面后改原 payload                                              |
| BrowserLease       | leaseId、scope、browserInstanceId、sessionId、taskId、allowedTargets、capabilities、policyVersion、expiresAt、generation             | 短期、可撤销；服务端与本机都校验                                                              |
| BrowserAction      | operationId、requestId、leaseId、sequence、kind、target、preconditions、argsHash、deadline、approvalRef                              | action 有唯一身份；写操作先持久化再执行                                                       |
| ActionReceipt      | operationId、state、observedAt、resultRef、postcondition、errorCode、retryability                                                    | accepted 不等于 performed，performed 不等于 verified                                          |
| Prompt Shortcut    | v、id、workspaceId、ownerUserId、visibility、name、emoji、slug、description、prompt、mentions、scope、revision、createdAt、updatedAt | 原版模型；索引含 bodyDocId/dependencySummary，发布正文不可变且修订一致                        |
| Recorded Workflow  | id、version、scope、name、parameters、startTargets、requiredCapabilities、steps、successCriteria                                     | AUTO-02 的目标录制模型；不冒充 Prompt Shortcut 协议，凭证不嵌入步骤                           |
| Schedule / Run     | scheduleId、revision、timezone、recurrence、workflowVersion、target、misfirePolicy；runId、scheduledAt、lease、state                 | 每个计划时刻唯一运行身份；修改不重写既有运行                                                  |
| PermissionDecision | id、scope、subject、actionHash、policyVersion、duration、outcome、expiresAt                                                          | 只批准具体版本与范围；scope 变更使旧决策失效                                                  |

本地缓存与操作日志的隔离键必须包含部署 origin、账号和工作区；有设备或浏览器状态时增加相应身份。Prompt Shortcut 的 `scope` 是上游定义的项目、机器及 provider 适用范围，不能擅自加入身份或凭证字段；owner/workspace 与资源授权另行校验。凭证通过受控 provider 传递，不复制到正文、上下文或录制步骤。

### 单条消息与附件发送

1. 冻结草稿、来源、目标及配置，分配并持久化 submission request ID。
2. 校验模型输入能力与预算；准备/上传附件，记录每个已知上传身份。
3. 新会话在 FILE-02 的合同下完成预留；原问题和网页资料组成一个完整 prompt，同时保持唯一文本 input block 与 prompt 一致；图片/文件使用同一 turn 的专用块。
4. 提交一条用户消息。资料不得通过第二条用户消息补发；传输成功、消息持久化、Agent 接受与生成完成分别观察。
5. 未知结果按原 request ID 查询/协调；恢复时使用已冻结 payload，不重新采集页面。确认后才清理对应草稿版本，发送期间新输入不能被清空。

### 状态机和重试

| 对象       | 合法主路径                                               | 异常路径与恢复                                                                                 |
| ---------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 草稿       | editing → preparing → ready → submitting → confirmed     | preparing 失败回 editing；submitting 未知进入 reconciling；不能从 reconciling 直接分配新 ID    |
| 附件       | local → uploading → uploaded → referenced                | failed 可按已知身份重试；unknown 先查询；removed 不等于 remote-deleted                         |
| Agent turn | persisted → accepted → running → completed               | waiting-permission、failed、cancel-requested、canceled；持久化不能直接跳 completed             |
| 浏览器任务 | created → checking → running → verified                  | waiting-permission、waiting-browser、paused、reconciling、failed、canceled；恢复重验租约与页面 |
| 浏览器动作 | prepared → authorized → dispatched → observed → verified | timeout/disconnect 后 unknown；写入 unknown 先观察后果，无法查明则人工恢复                     |
| 定时运行   | due → claimed → running → finished                       | waiting-browser/permission、skipped、failed；领取超时由权威服务回收，不重复提交网站副作用      |

只读操作可在同一身份和新鲜目标下重试；有副作用的操作必须检查 journal 和后置条件。去重只覆盖本方调用，不保证外部网站 exactly-once。对无法确认是否已发送邮件、提交订单或上传文件的情况必须报告未知结果，不再次点击制造重复。

### 错误合同

目标错误族为 identity、policy-denied、permission-required、unsupported、stale-target、conflict、quota、transport、protocol、delivery-unknown、execution-unknown。每个错误提供阶段、相关 ID、可恢复动作和原始原因的受控详情。正式 schema 不依赖解析任意英文异常字符串。

超时终止本地等待，不自动回滚云提交或网页副作用。取消先禁止后续动作，再观察当前动作和 Agent 的终态；用户能区分“正在停止”和“已停止”。

### 质量预算与证据

- 本地交互目标：暖启动下输入反馈和弹层首次可见响应 p95 不超过 100 ms，侧栏主要结构 p95 不超过 500 ms；这是待测目标，不是当前成绩。远端首 token 单独记录，不混为本地响应。
- 发布前固定浏览器/机器/构建/数据规模，至少 30 次有效重复，保留原始分布、p50/p95、trace 和排除理由。按 assurance 合同登记事件起点与可观察终点，不能用 request resolve 代替可见响应。
- 工作负载至少包含 200 个会话标题、1,000 个历史 turn、100 条连续工具记录、长中文/代码/表格、多标签与 SDK 限额附件。记录内存和长任务；超预算先定位再调整，不在无证据时提高阈值。
- Storybook 覆盖浅/深主题、各 mood、窄宽布局、空/加载/失败/等待批准/运行/停止/未知内容。axe 无 serious/critical 问题，键盘和读屏仍需真实交互检查。
- 运行 `pnpm check` 和受影响的浏览器旅程；storage、routing、CSP、worker、manifest、host 权限与打包入口变化必须运行 `pnpm test:extension`。发布证据还需真实后端、真实 Agent 和浏览器 bridge 的受控实测。
- `COVERAGE.md` 只从真实报告生成，不由本规格的功能数或 J 表推算覆盖率；当前基线的测试通过不代表新功能已通过。

| M0 契约实验   | FILE-02、ACT-01、GOV-01/02、AUTO-03 协议准备   | 下节实验形成可执行协议及成功/失败证据；未决依赖保持 capability 关闭         |

| M3 浏览器执行 | ACT 全部、INT-01 桥接、INT-02、GOV-01/02/04/05 | 真浏览器读写、批准、停止/接管、重启恢复及远端 Agent 闭环通过                |

各阶段都继承权限、隔离、无障碍和错误合同；不能把基础授权或错误恢复推迟到 M5。优先级不代表省略功能；确需更改范围必须修改映射、要求和验收三处的一致关系。

### 实现前必须关闭的技术问题

| 实验                     | 责任边界                         | 必须产出的结论                                                       | 失败后的路径                                         |
| ------------------------ | -------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| 草稿附件存储身份         | 附件 SDK + 后端 + chat feature   | 独立 storageSessionId 的授权、首次 turn 消费、失效和回收证据         | 使用首次发送内的预留流程；仍不允许提前生成可见空会话 |
| 远端 Agent 到本机浏览器  | Lody runtime + browser-runtime   | 认证传输、租约/撤销、反重放、代理兼容、worker 重启结果               | 验证原生宿主方案；未完成时保持只读快照功能           |
| 浏览器执行 API           | browser adapter                  | 对支持 Chrome 版本的元素/截图/输入语义、debugger 争用、跨 frame 结果 | 缩小能力声明，不以任意脚本或坐标重试掩盖失败         |
| 计划/运行配置与子会话    | SDK + runtime + shared UI        | 能力 schema、取消/补充/分叉及 child-session ACL 的正式合同           | 展示受控记录和不可用原因，不渲染假操作按钮           |
| 调度唯一权威             | Lody 调度服务 + workflow feature | runId 去重、领取租约、时区、错过/重叠及暂停合同                      | 只交付手动快捷指令，不用本地计时器冒充可靠调度       |
| PDF/字幕/语音/密码管理器 | 对应服务与宿主 adapter           | 可用 API、部署方式、数据政策、能力及失败样本                         | 保留文件/文字/人工登录入口；对应增强能力不宣称支持   |
| 组织及远端删除           | 后端 + account/policy feature    | 策略更新/撤销、数据保留、附件清理与分享 ACL 证据                     | 明示限制；依赖此保证的组织发布暂不开放               |

### 完成定义

每个功能 ID 完成时必须具备：可达的用户入口、成功路径、失败与恢复、能力和权限声明、可观察结果、相应模型义务及真实证据。SDK 有方法、菜单有按钮或静态截图漂亮都不足以完成验收。

完成记录写入实现 PR 与生成的验证报告，注明 source revision、环境、功能 ID 和限制。本规格维护目标及设计决策，当前架构维护实际行为，两者通过模块链接连接；不把尚未实现的目标写成当前能力。
